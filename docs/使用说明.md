# 日常使用

将新下载放入 `C:\Manga\【未分类】`，双击工具根目录的 `整理新漫画.cmd`，或运行 `process_download_batch.ps1`。E 库使用 `process_download_batch.ps1 -Library E`。其他输入可用 `-Root '<库根>\【未分类】' -LibraryRoot '<库根>'`，`process_download_batch.ps1 -Library H,E` 顺序处理多书库。日常与可选功能见 [README](../README.md)。

程序按 100 本分批准备和提交，完成后继续剩余输入。准备期间新增的文件留待下一次运行。每本失败单独保留，不妨碍其他书；最后集中输出成功数、跳过数、每个问题和原因。

## 运行环境与验证

需要 Windows 和 Python 3.12+，归档转换使用 Windows 自带 bsdtar。首次从 GitHub 获取后，将 `config.example.json` 复制为 `config.json`，修改书库路径；示例默认禁用 Komga，填写实际路径后再按需启用。已有本地配置保持不变。

双击入口和 PowerShell 入口共用 Python 查找：PowerShell 显式 `-Python '<可执行文件>'` 优先，其次为环境变量 `MANGA_INTAKE_PYTHON`，再依次尝试 `runtime/python/python.exe`、系统 `py -3` 和 `python`。候选须通过 Python 3.12+ 校验；显式指定无效时直接报错，不静默改用另一环境。无需为了推送 GitHub 移动本地 runtime，Git 已忽略它；仓库不包含运行时二进制。

在 PowerShell 当前会话中可以这样指定外部 Python：

```powershell
$env:MANGA_INTAKE_PYTHON = 'C:\Python312\python.exe'
& .\process_download_batch.ps1 -Help
```

双击入口读取启动它的进程继承的环境变量；也可直接使用已安装的 Python 或本地 runtime。

Git 跟踪源码、测试、示例配置、文档、作者规则及本地词库和许可；本机 `config.json` 和可选翻译覆盖 `data/translations/overrides.json` 不纳入版本控制。忽略 `runtime/`、`cache/`、`state/`、`__pycache__/`、字节码和旧的 `tests/.temporary/`。本地提交用于比较和回退代码，不会备份或回滚漫画、Komga 数据库和运行状态。存在未完成恢复记录时，应先完成恢复，再考虑回退涉及事务格式的代码；保留所有 journal。

在工具包目录运行完整回归：

```powershell
. .\runtime.ps1
$mangaPython = Get-MangaPython
& $mangaPython -B -m unittest discover -s tests -v
```

测试使用临时书库和临时 SQLite 数据库，不处理真实书库或 Komga 服务。临时文件默认放入系统临时目录，正常结束自动清理；`MANGA_INTAKE_TEST_ROOT` 可指定独立测试目录。`-B` 避免生成字节码。

## 元数据

ComicInfo 是唯一的书籍 metadata 存储。已有有效的题名、作者／社团、语言和 tag 时复用它；缺失时从完整文件名来源、已有 Web、人工来源映射或同名且来源唯一的 torrent 定位画廊。torrent 匹配忽略 RAR/ZIP/CBZ 等归档格式扩展名，保留本名、编号和版本注释；格式转换或删广告导致的大小变化不阻挡。没有直接来源时才按名称搜索。

明确 gid/token 是直接来源，API 返回对应编号和 token 后采集 metadata，不重复做题名检索。手动题名、版本注释和本地分册范围保留；合集可以参考某个单卷的标签，但不套用该单卷的题名、编号、页数或判重身份。明确单卷编号冲突仍交给人工。按名称检索的候选必须匹配题名、作者／社团和明确编号，不要求页数相等。多个候选通过同作品核对时，优先采用有效标签最多的一项作为 metadata 来源，不合并其他候选独有的标签；重复标签、语言／版本标签及上传状态不计入完整度。标签数量相同再参考本地语言和页数。已有人工字段仍保留。

文件名来源前缀（如 `[EX_123456_0123456789]`）后允许零个、多个空格或换行。普通卷号从右往左识别；重复语言题名具有相同题头和卷号时采用题头，重复卷号冲突则交给人工。Season／シーズン按同一系列的编号识别；“3号室”“10分の1”“100人斬り”“2つ／2tsu”等题名数字不作为卷号，合集范围要求两个完整端点。明确主标题卷号与别名卷号不同时，不用该别名合并不同册；年月期号、前后篇及合集范围继续采用专门规则。

作者优先 API 的 artist tag；缺 tag 时读取来源题名中的署名，不因为缺少 artist tag 而拒绝已有署名的书。“よろず／Various”等占位署名不作为个人作者；社团明确时按社团归属。已有真实人工署名保留。语言优先本地 ComicInfo 和文件名；来源没有语言标签且题名为日文时采用 ja。未能确认的语言或署名会说明原因，交给用户处理。不会读取图片猜测内容。

新增内容仅限基本 metadata；检索过程、哈希证据、置信度及修复／归档历史留在库外，不写入 Notes 或自定义审计字段。已有简介、手工备注和未知 XML 字段保留。

作者写入 Penciller；已有人工 Penciller/Writer 保留。社团保存在 MangaGroups 并进入 Tags；原始 tag 键保存在 MangaTagKeys，中文标签用于 Tags。已有 tag 和未知 XML 字段保留。

## 归档与系列

单个作者优先作者目录；多人作者且唯一社团时归社团；其他多人合作归合刊目录。所有单篇进入主体目录下的 `_oneshots`，无作品数门槛。

新本先检查该主体的已有系列目录名及 `_oneshots` 的 ComicInfo。相同题名家族且有不同分册／前后篇，或无编号首本配合后续册时，可以建立系列；同一册的两个译本不构成新系列。多人合刊每期作者可以不同，按同一刊名及不同期号组合；年月期号使用 YYYY.MM。已有系列沿用实际目录名，不重新整理其他系列。

无编号首本的副标题需要明确分隔符，不能只凭题名前缀或作者相同合并。新增社团标签时，仅检查当前署名社团的相关目录；作者集合一致且已有系列匹配唯一，才沿用原系列归属，不递归扫描全库。多个目录／题名家族或作者信息冲突时，新输入保持原位，记入 `failures.csv` 的 `series_review` 项，列出候选位置供人工处理；其他书继续入库。人工确认后可调整 ComicInfo 的 Series／Number 和作者／社团，再用原入口重跑。

系列组合属于默认开启的可选功能。`-NoSeriesMerge` 关闭新系列建立及旧单篇移动，仍沿用已有系列目录；新系列只移动匹配的旧 One-Shots 和本次新书，并更新这些书的 Series/Number；不改变其他书的目录、文件名或 metadata。无法确认分册范围的合集仍可补核心 metadata，并保持为一个独立本，不强行拆卷。

同归档主体的题名／分册身份相同，或相同来源且分册无冲突的条目已存在时，先进行下述图页指纹判重；图页不同的新版本自动归档，已有版本全部保留。目标重名时添加 `[版本2]`、`[版本3]` 等后缀，报告列出同时保留的位置。同作品候选通过相关目录的 ComicInfo 识别，页数差异不阻挡识别；读取或核验失败则保留原输入并报告。只有文件名相同但 metadata 不同时，单独报告重名冲突。程序不自动覆盖；只删除满足下述规则的未分类副本。

## 自动格式转换

ZIP/CBZ 直接入库；RAR/CBR/7z/CB7 使用 Windows 自带 bsdtar 自动转换为 CBZ，保留图页、附件和人工 ComicInfo 字段。PDF/EPUB 继续保留原位并报告，不恢复旧 PDF 解包流程。

转换采用 PAX 流读取，不把压缩包内部路径解包到文件系统；拒绝路径越界、重复条目、链接或特殊文件。输出逐条核验完整大小与 SHA-256，读取 ZIP 时同时校验 CRC。原包在转换、metadata 写入和事务提交成功后才移除，失败保留原件；强制退出后下次运行按记录恢复。

网络查询、图页核验和转换都在暂停阅读器之前完成。`-DryRun` 仅预览转换目标，不生成转换包。`-MetadataOnly` 时转换输出留在原目录，同名 CBZ 已存在则添加版本后缀。

## 可选功能入口

统一使用 `process_download_batch.ps1`：`-MetadataOnly` 原位补 ComicInfo（需转换时输出同目录 CBZ）；`-Library H,E` 顺序处理多库；`-Offline -DryRun` 离线预览；`-Report` 额外导出；`-TagLanguage raw` 使用原始标签。`-PrefixedOnly` 只选择带画廊来源前缀的输入（Python 参数为 `--prefixed-only`），不改变已存在的恢复任务。输入子目录使用 `-Root`，自定义库根使用 `-LibraryRoot`；另可指定 `-TorrentDir`、`-CacheRoot`、`-CreatorAliases`。`-Help` 查看全部参数。原独立采集、多库维护、通用分发和旧 Python 入口已退役。

## 人工解决问题

待处理清单为 `state/intake/failures.csv`，新增 `kind` 和 `existing_paths` 列；已有多个版本时列出所有匹配位置。`state/intake/latest.txt` 同时列出成功归档的位置和全部问题。可修改 ComicInfo，或准备来源映射：

```json
{
  "本地文件名.zip": "https://e-hentai.org/g/123456/0123456789/"
}
```

运行 `process_download_batch.ps1 -Sources '<映射文件>.json'`。人工链接优先于文件名旧来源。映射支持输入相对路径和完整路径；旧的未使用条目不会阻止本次处理。来源也可以使用 `https://nhentai.net/g/123456/`，通过官方 API 直接读取；已有 Web 中的 NH 链接同样按编号查询。加 `-SourcesOnly` 仅处理映射中指定的新本。

`-DryRun` 会查询并预览；`-Offline -DryRun` 不联网，缓存缺失的书会显示相应原因。控制台以汇总和问题为主，完整成功路径保存在最近一次结果。待处理 CSV 按书库和本次选择更新，保留其他未解决项。显式 `-Report` 可另存诊断，建议重复使用同一固定目录。

## 阅读器与恢复

已登记书籍发生格式转换时，另排入该书的 AnalyzeBook 任务，先重新分析 CBZ 再刷新 metadata；不能只依靠普通扫描判断格式变化。书籍身份及阅读记录继续沿用原有记录。

网络准备及转换不暂停 Komga。提交时读取最新登记身份，文件变更和受影响记录在短窗口完成；Book ID、加入时间、进度和书单保留。所有批次结束后统一排入本次书籍的 metadata 刷新及普通扫描任务，不进行深度扫描或全库索引重建。Komga 关闭时仅持久排队，不主动启动或等待它；用户之后正常启动 Komga，阅读器自动处理队列。报告“已排队”表示任务已保存，实际扫描和显示由 Komga 完成。

短期 `state/intake/pending_*.json` 用于正在提交的少量路径、原 XML 和恢复状态，完成刷新排队即删除，不是书籍数据库。异常中断后重跑会恢复本次涉及的文件或完成已提交的刷新；外部修改了这些文件时停止对应恢复，并说明记录位置。其他手工目录调整不参与检查。

仅删除重复输入时，也会先原子保存 `pending_scan_<书库键>.json` 再删除，同一书库合并为一个普通扫描任务。记录保存失败则保留输入；删除后排队失败或进程中断，下一次正式运行同一书库会继续排队。即使没有新输入，也会恢复；预览、其他书库运行和禁用阅读器同步不会清除这项任务。Komga 未登记对应书库或任务仍被占用时，保留记录并报告原因。

阅读器同步失败标记为 `reader_sync`，只有所属书库的更新任务成功写入 Komga 队列后才清除。旧版以状态目录为 path 的“阅读器同步”记录也会识别：即使原 journal 不存在，也先重新排入一次普通扫描，再清除旧行。普通书籍失败及其他书库问题继续保留，不因 recovery 文件缺失而统一删除。恢复链接只指向实际存在的文件；无需人工删除 `failures.csv`。

## 已有 metadata 优先

浏览器下载或人工填写的包内 ComicInfo 可以直接使用。先复用已有字段，再用包内 MangaTagKeys 补缺失作者／社团、语言及中文 Tags；文件名的明确语言注释可补 LanguageISO。题名、作者／社团、语言和 tag 齐全后，跳过来源匹配和 API，直接按正常流程改名、归档、判断重复及组合系列，不要求存在来源链接。

仍缺核心字段时才查询来源；补缺查询使用 ComicInfo 的题名和署名，优先包内 Web，然后文件名前缀及 torrent。API 只填空字段，已有 Title、Penciller／Writer、LanguageISO、Tags、MangaTagKeys、来源题名及未知字段保留。原始 tag 已齐全但缺中文 Tags 时，先用本地翻译字典生成。

PageCount 始终采用当前压缩包实际图页数。Series／Number、文件名和目录按归档结果更新；参与本次系列组合的旧 One-Shots 同样更新本地页数。

完整 metadata 默认不会因 `-Sources` 重新采集；需要重新查询时显式加 `-Refresh`。`-SourcesOnly` 仍可用于选择单本或指定输入，完整的书继续直接复用 ComicInfo。提供来源映射并查询时，该映射可纠正 Web；其他已有内容字段仍保留。

## 重复副本自动删除（可选，默认开启）

加 `-KeepDuplicates` 时，同作品仅报告并保留本次输入，不做图页指纹核验和自动删除；冲突检查始终保留。

先依据同归档主体的题名／分册识别候选，再核验图页指纹。需要图页数相同，按自然阅读顺序排列的全部图页未压缩大小和 ZIP 目录中保存的 CRC 相同，且前三页图片数据合并计算的 SHA-256 相同；少于三页时读取全部图页。

ZIP/CBZ 只读取最多前三页的图片数据，其余图页使用 ZIP 目录信息；待转换归档需流式读取图页以取得 CRC。ComicInfo、压缩参数、压缩包时间、非图片附件不参与图页指纹。这是快速图页指纹判重。只有页数或前三页相同，尚不满足自动删除条件。

符合条件时只删除本次【未分类】输入，保留库内副本及其阅读器记录。核验发生在服务暂停之外，实际删除前再次确认两条路径和文件状态；文件变动、读取失败或其他差异则保留新输入，报告已有位置和原因。哈希仅在本次运行内缓存，不维护中央 JSON 或全库哈希索引。

`-DryRun` 与正式入库共用候选、判重和归档规划，含本批及先前批次拟归档文件，也会更新后续系列组合导致的路径变化。文件和 metadata 不变时，两者候选、保留版本和删除结果一致；预览标明将删除的副本，不修改漫画或阅读器。正式文本报告单独列出删除数量、原输入位置、保留的库内位置和判定依据；不同版本正常归档并单独汇总。删除后排入一次普通阅读器扫描。

## 收尾与记录

正式运行正常结束或发生可捕获的异常时，清理程序自己的过期／超额查询缓存和满 24 小时的已知临时输出。强制结束进程后，下次运行先恢复，再在收尾时清理。缓存保留 30 天，API 和搜索合计最多 2,000 个文件、32 MiB；保留最近写入的条目。单个 API 的新鲜缓存有效期仍是 7 天，30 天是文件保留期。清理失败会提示下次重试，已完成的入库不因此回滚。

最近一次结果覆盖 `state/intake/latest.txt`。`failures.csv` 只保留未解决项，成功或手动移走的输入移出清单；H/E 及 `-SourcesOnly`、子目录运行不会覆盖其他仍需处理的文件；其他书库磁盘离线时不把无法访问的文件当成已处理成功。相关旧 One-Shots 本次组成系列时，清单中引用的已有文件位置同步更新。

所有批次结束后按最终移动结果统一校正报告中的成功、保留版本、重复副本和待处理引用，包括当前书籍自身触发的系列移动。运行中的路径映射只在内存中复用，不生成逐步存档；显式报告目录仍覆盖最近结果。

`deleted_duplicates.csv` 单独保存自动删除副本的时间、当时输入／保留路径、页数和抽样 SHA-256 依据，保留 30 天且最多 1,000 条。意外中断的错误栈只保存一个 `last_error.txt`，成功且没有未完成恢复记录后删除。程序不保存永久成功调用日志或漫画内容副本。

`pending_*.json`、相应临时文件及 `service_pause.json` 是恢复材料，清理不按年龄删除它们。事务提交并完成阅读器刷新排队后删除；失败时保留，下一次运行继续恢复。`run.lock` 是一字节的复用锁，防止两批同时改文件或清理缓存；进程退出后操作系统释放锁。

## 已归位目录与 metadata 回退

`-InPlace -Root '<库内子目录>'` 可处理已归位的压缩包和叶级图片目录，保留当前位置并改名。叶级图片目录打包为同目录 CBZ，附加文件与人工 ComicInfo 内容保留；逐文件 SHA-256／CRC 核验、事务提交后才移除原目录。已有目标自动使用版本后缀，中断由原事务机制恢复。

默认先复用完整 ComicInfo，再用 torrent／前缀直接查来源；无直接来源时，EH 名称检索后回退 NH 官方 API。确认直接来源不存在才允许自动改走名称；网络错误、限流或 token 错误不会作为无结果。人工提供来源优先，`-Sources` 可更新已有完整 ComicInfo 的来源字段。

`-SeriesTags` 允许同作者同系列内容标签参考，不改变本卷题名、卷号或来源身份；`-HashLookup` 明确授权将首／中／末页 SHA-1 发送至 EH，无图片上传，离线模式不会发送。API key 只读取 `NHENTAI_API_KEY` 环境变量，无密钥时匿名请求。候选歧义、无结果或请求失败均保留输入并进入现有待处理清单。

## 图集作者补全

`-CollectionAuthors <清单.json>` 使用显式确认的绝对路径、`authors` 列表及 `expected_stamp` 文件状态，仅补作者、缺失本地题名、可确认语言和实际页数。配合 `-InPlace -MetadataOnly -NoSeriesMerge -KeepDuplicates -Offline` 并指定库内子目录；只处理清单路径，不查询来源，不新增标签、系列、卷号或外部身份。现有有效字段保留；署名已确认即满足图集完成条件。

明确“第 N 話／巻”优先于副标题中的“その N”；题名里的“3にん”等人数和“2泊3日”等时长不作为卷号；保留“第8巻 -- 100”中的卷内章节号。

带明确平台目录或图集标识、且已有有效作者的 ZIP/CBZ，可用 `-MetadataOnly` 按本地基本字段维护：Tags／Web 留空不触发 API 查询，语言只采用已有字段或明确文件名注释。缺少已确认署名时使用 `-CollectionAuthors`。

普通归档中，文件名或题名里的 Fanbox、Patreon、Fantia 仅作为平台提示：先复用完整 ComicInfo，否则按现有 torrent／来源及名称查询流程取得 metadata。成功匹配的漫画正常按作者／社团归档；确认没有匹配后才提示图集维护。网络错误、限流或候选歧义继续报告原问题，不按“没有 metadata”改判图集。显式 `-MetadataOnly` 仍可按平台文件名选择本地图集维护。

明确平台目录、`【订阅图集】` 目录和图集标识／标签继续按图集处理，不自动查询来源或补作品标签。仅有平台标签不把普通漫画改判为图集。普通归档模式遇到明确图集会提示改用维护模式，避免错误分系列。

原位补 metadata 保留 Komga 已有的单篇／系列结构；ComicInfo 的 Series 为空时，不把系列目录中的书改成单篇。

明确语言注释支持中文方括号、官中、台版和中文翻译署名；多种语言注释冲突时不自动推断。目录名仅作为署名检索线索，未注明角色时同时核对作者与社团，由 API 确认角色；不把目录名直接写为作者。
